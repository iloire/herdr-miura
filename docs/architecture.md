# Architecture

```
 Herdr daemon ──socket──▶ herdr/ worker ──events──▶ pump thread ──Channel(JSON)──▶ webview
  (owns PTYs)            (reader + session       (connection.rs)                 Controller → Grid → Painter
                          threads, bincode)                                       React: Sidebar, TabBar, …
 Herdr daemon ◀──────── bounded command queue ◀──────── Tauri commands ◀── invoke() ──── Daemon (daemon.ts)
```

## Rust: `src-tauri/src`

| File | Job |
| --- | --- |
| `herdr/` | Our client of the daemon. `wire.rs` and `endpoint.rs` are Herdr 0.9.5's declarations (see `herdr/NOTICE.md`); `codec.rs` frames them; `socket.rs` finds the socket by Herdr's rules; `session.rs` holds the handshake, boot and revision fencing, and one API request in flight with a FIFO queue behind it; `surface.rs` validates frames and applies patches whole or not at all; `client.rs` runs a reader thread and a session thread per connection. The optional surface encodings are never requested, so surfaces arrive whole or as row patches. `ssh.rs` and `health.rs` reach another machine's daemon instead: see [ssh.md](ssh.md). |
| `ssh_hosts.rs` | The host picker's list (named `Host` entries of `~/.ssh/config` and its includes) and host key approval: `scan_host_key` fetches a new host's keys and returns their fingerprints, `trust_host_key` writes exactly those keys to known_hosts. |
| `connection.rs` | Owns the `ClientHandle`, drains its `Event`s on a pump thread, and forwards them as tagged JSON. Writes OSC 52 clipboard text itself. |
| `frame.rs` | Turns each reconstructed `PaneSurfaceFrame` into a `FrameUpdate`: every row after a size or boot change, otherwise only the rows that changed. Cells are positional tuples to keep payloads small. |
| `commands.rs` | The Tauri commands: `connect` (to this machine, or a `host` over SSH), `disconnect`, `resize`, `set_focus`, `send_input`, `send_popup_input`, `request` (an allowlist of endpoint methods: the webview's own and those `src/app/catalog.ts` builds). |
| `git.rs` | Runs Git: no prompts, optional locks, or file monitor, under a deadline and an output cap, with both pipes drained. `run` is for reads. `supervised` is for commands that spawn helpers or write: Git and its children share a process group that an overrun stops whole, SIGTERM first so Git removes its locks, each stream keeps its end rather than its start, and messages are in English so they can be recognized. `shell` runs a repo's own check the same way, under the user's interactive login shell, because an app started from the Dock has neither `npm` nor `cargo` on its `PATH`; what the startup files print is dropped. |
| `sync.rs` | The Changes panel's network operations: `sync_checkout(checkout, op, branch)` fetches, pushes, publishes or pulls, and answers with an `Outcome`, since a refusal is an answer rather than an error. One operation per checkout (`Running`), 60 s each. Never force-pushes, merges, rebases or stashes, and says so on the command line where config could turn those on; a config that makes a plain push force is refused. Re-reads the branch and any rebase or merge just before it runs. Refused on a remote host. See [plan-changes.md](plan-changes.md#remote-sync). |
| `land.rs` | Landing a worktree from its card. `land_plan(worktree)` reads what the confirmation names, or why it would be refused: only a linked worktree on a branch with commits local main lacks, with no uncommitted files, no rebase or merge there or in the main checkout, not locked, and the main checkout on main. `land_check(target)` runs the repo's check in the worktree, at most 30 min. `land_finish(target, steps)` then rebases onto main, fast-forwards main in the main checkout with `--ff-only`, runs `git worktree remove` and `git branch -d`, and confirms it all by asking Git again, 2 min a step, naming each step on a `Channel`. They are two commands so the webview can look at the worktree's agents between them: a check can take minutes and only the snapshot knows. Each `Target` pins the branch, commit and check that were confirmed and is read again before anything runs, and the main checkout's branch again right before it moves. Answers with an `Outcome`: a failure names its step, why, and what state things were left in. A conflict is aborted, never resolved. Nothing is forced, reset, stashed or pushed: `--no-autostash` and `--no-update-refs` overrule config, and a published branch is kept, as `-d` compares with its upstream. One land per repo across every window, by a file lock in Git's common directory, since Stable, Edge and a dev build are separate processes. The check is found in the worktree: `.herdr/land.json` (`{ "check": "<shell command>" }`), then a `check` script in `package.json` with the lockfile's manager, then a `check:` make target; none means the confirmation says so, and a `land.json` that cannot be used refuses. Refused on a remote host. |
| `worktree_ops.rs` | The Changes panel's writes to the working tree, as `changes.rs` promises it never writes: `discard_plan(checkout, path, branch)` says what discarding one file would do and returns a fingerprint (the raw status entry, with its HEAD and index hashes, plus `git hash-object --no-filters` of the working file), and `discard_file(checkout, path, fingerprint, branch)` takes the `sync::Running` claim, makes `sync::current_branch`'s checks, and refuses if the fingerprint no longer matches. A tracked file's working copy goes to the Trash before `git restore`, from a temporary folder inside the Git directory, and an untracked file moves there itself. If the Trash fails, nothing else happens. A rename restores both paths in one command. Folders, symlinks, submodules and conflicts are refused. Every path-taking Git command has `--literal-pathspecs`, because `*` is a legal filename character. On macOS the `trash` crate's NSFileManager method is used, as its Finder method prompts for automation permission. `commit_paths(checkout, paths, message, branch)` takes the same claim and checks, adds the untracked paths, then runs `git commit --only` on the paths, a rename's old one included, so what an agent has staged stays staged and out of the commit, and the panel leaves nothing staged. A commit that fails unstages what it added, and the note shows Git's or the hook's output. A folder holding another repository is refused, as `git add` would turn it into a gitlink. Hooks run, signing follows the user's config, and the 60 s limit applies. Refused on a remote host. See [plan-git-actions.md](plan-git-actions.md). |
| `changes.rs` | The Changes panel's reads, parsed from Git's porcelain output in `changes/parse.rs`: `checkout_changes(directory)` (branch, ahead/behind, up to 50 files with line counts, the latest 50 commits, a rebase, merge or cherry-pick under way with a rebase's step, and how many files are in conflict, counted before the 50 cut) `commit_files(checkout, sha)` (a commit's whole message and the files it changed, with line counts, up to 300), `moving_commits(checkout, direction)` (what a push or pull would move, from local refs, up to 500) and `file_diff(checkout, path, untracked, commit)` (`git diff HEAD`, or `git show <commit>` against its first parent, capped at 1 MiB, or an untracked file's text). A commit is taken only by its full 40- or 64-digit name, so Git cannot read it as an option or a range. Also `change_counts(directories)`, the sidebar's per-workspace changed-file count: one `git status --porcelain` per directory, at most 64. Runs on Tauri's blocking pool with a 5 s deadline, refuses paths that leave the checkout, and never writes or contacts a remote: that is `sync.rs`. |
| `files.rs` | The Files panel's reads: `list_files(directory)` (every file `git ls-files` lists, tracked and untracked but not ignored, up to 50,000) and `read_file(root, path)` (a text file up to 1 MiB, an image up to 8 MiB as base64, or why it cannot be shown). A path is resolved through symlinks and refused when it leaves the checkout. |
| `folder.rs` | A workspace folder's right-click actions: `open_folder(path, with)` in the file manager, VS Code, or GitHub Desktop (a fixed list, never a program the webview names), and `copy_path(path)`. Both refuse anything but an existing absolute directory. `open_file(root, path)` opens one file of a folder in VS Code (the Team dialog's Edit), resolved through symlinks with `files.rs`'s check and refused when it leaves the folder. |
| `claude_usage.rs` | `claude_usage()`: this Mac's Claude plan usage (5-hour and weekly windows, plan name), read with Claude Code's own OAuth sign-in from the login keychain or `~/.claude/.credentials.json` and asked of Anthropic's `oauth/usage` endpoint, as herdr-gpui's `herdr-usage` Claude provider does. It also keeps what only the dialog shows: each model's own weekly limit, this week's share by surface, paid extra usage and when the reading was taken. A reading is kept 10 min (30 min after a 429, 5 min after another failure), so the webview may poll freely. Works whichever host the window is attached to: the account is the user's. |
| `session_usage.rs` | `session_usage(sessions)`: each Claude Code session's token use, for the tab header. A session's pane carries its id as the `claude_session` token (dotfiles' `herdr-attention`, from Claude Code's `SessionStart` and `UserPromptSubmit` hooks; not the path, since Herdr cuts a token at 80 characters), so its transcript is found as `~/.claude/projects/*/<id>.jsonl` and remembered. Each response's `usage` is summed by minute over six hours, a response written twice counting once with its last copy, subagents' `<id>/subagents/*.jsonl` included; the last main-thread response gives the model and the context. A session's use also carries `written_at`, the latest modification time of its transcript and its subagents' files, since a session busy in a subagent leaves its own file alone, and `prompt`, its last line with `origin: {kind: human}` that is not meta, a sidechain or a command's wrapper, without the `<pasted_content>` tags a queued prompt arrives in and cut to 500 characters. Only people's lines have that origin, so tool results, hook output, task notifications and skill text never match, and the check runs on the raw line so the large tool results are not parsed. Files are read on from where the last poll stopped. Ids that are not UUIDs are refused, so a pane cannot point it at another file. This machine only. `usage_history()` is the usage dialog's: every transcript under `~/.claude/projects` written in the last eight days, closed sessions included, summed by project in five-minute buckets. A project is the last folder of the `cwd` a transcript started in, a linked worktree counting as its main checkout, and a message id counts once across files, since a resumed session repeats responses in a new file. It shares the session reads' cache: the first read took 4.8 s over 1.8 GB here and holds the cache's lock meanwhile, so the tab header's reads wait; a reread takes milliseconds. It needs no connection to the host, as the account is the user's. |
| `listening_ports.rs` | `listening_ports()`: the TCP ports each workspace's servers listen on, as herdr-gpui shows them. One `sh` step (ported from herdr-gpui) lists listeners with `lsof` (`ss` on Linux) and reads each listener's environment, or its nearest parent's, for the `HERDR_WORKSPACE_ID` every Herdr pane exports; its `HERDR_SOCKET_PATH` must name the daemon we are attached to. The same ancestor's `HERDR_PANE_ID` is the port's `pane`, null for a pane from an older Herdr. It survives a move to another tab, unlike `HERDR_TAB_ID`; a move to another workspace gives the pane a new id, so its servers match no pane, and they keep counting under the old workspace. Listeners started outside Herdr are dropped. This machine only, under a 15 s deadline. |
| `worktrees.rs` | `worktrees(directories)`: the linked worktrees of each workspace's checkout, the main one left out, from `git worktree list --porcelain -z` run in the workspace's folder, so worktrees an agent made under `.claude/worktrees/` count although no pane sits in them. Bare and pruned ones are skipped. Each reports its branch, its last commit's subject and time, the commits the remote's default branch lacks (`changes.rs`'s `default_branch`, named in `base`), the commits local main lacks (`ahead`, against `main`, which is what Land moves, and main can be ahead of its remote), the main checkout's folder (`repo`) and its changed files. At most 16 per checkout, under a 5 s deadline per checkout, this machine only. |
| `tab_move.rs` | `move_tab(panes, workspace_id, label)`: Herdr does not offer `pane.move` to GUI clients, so this runs the `herdr` CLI (found on `PATH` or the usual install directories) as herdr-gpui does. The first pane opens a new tab in the destination, the rest join it, and a named tab keeps its name. Herdr's own error message comes back as the failure. |
| `queue.rs` | The prompt queue's file and starts. `queue_load` / `queue_save` keep `queue-tauri.json` in the app's data folder, written whole through a temporary file and renamed; a file that does not parse is kept as `.bak`, and a save first copies the file it replaces into `queue-backups/` (at most hourly, the newest 48 kept). Every window of this app shares that folder (the daily one and each worktree's dev build), and each saves the queue whole from memory, so only one may own it: `queue_load` takes an exclusive lock on `queue.lock` (`queue::Owner`) that the process holds until it exits, and without it `queue_load`, `queue_save` and the inbox commands refuse; the webview retries the load every 5 s. A `tauri dev` window on a feature branch (`__DEV_BRANCH__` set) with the daily app id never calls `queue_load`, so the daily queue is only ever run by `main`'s code; one started with its own id (`com.herdr.tauri.dev`) keeps a test queue in its own folder. `queue_open(workspace_id, directory, label, name, kind, args)` runs `herdr tab create --no-focus`, then `herdr agent start <name> --kind <kind>`; an agent not ready in time (asking to trust the folder, say) still leaves its tab and says why. `queue_worktree(directory, path, label, name, kind, args)` does the same in a new worktree: `herdr worktree create --no-focus`, whose workspace's first tab takes the agent, after adding `**/.claude/worktrees/` to `.git/info/exclude` if it is missing, so the worktree never reads as a change in the checkout. `path` must be directly in the checkout's `.claude/worktrees/`, and the branch is `feat/` plus its folder's name. Once the worktree exists it never answers an error, since a retry would find the branch taken: an agent that could not start comes back as not ready. `queue_prompt(name, text)` runs `herdr agent prompt <name> <text> --wait --until working`: the text goes before the options, since the CLI takes `--` only with nothing after it, and one starting with `-` gains a space. Names must be `q<digits>`, kinds Herdr's list, and text free of control characters but newlines and tabs. `queue_commits(directory, since)` counts what an item committed. `queue_log(directory, since, count)` lists those commits for the finished prompt's dialog. This machine only. Other programs hand the queue prompts through `queue-inbox/` beside the file, one JSON file each (`herdr-queue add` in dotfiles writes them, `.tmp` then renamed): `queue_inbox_list` returns them in name order, checked as above (version 1, a prompt of at most 100,000 bytes without control characters but newlines and tabs, a workspace id or an absolute folder), and moves a file that fails into `queue-inbox/rejected/` with a `.reason.txt` beside it; `queue_inbox_settle(name, reason)` moves one to `queue-inbox/taken/` once the saved queue holds its prompt (kept 30 days, so a prompt's text outlives the queue file), or rejects it with the reason. |
| `prompts.rs` | The prompt library's files: `prompt_library(directory)` lists `*.md` under `~/.claude/commands/` and under the workspace folder's `.claude/commands/` (three folders deep, at most 500 each, 256 KiB a file), each with its text or why it cannot be used (too large, not UTF-8, a dangling link, or a project link that leaves the folder; global ones may link into dotfiles). Nothing is left out, so the palette can show a broken file. `prompt_create(directory, name, text)` writes a new `<name>.md` there, or globally without a directory, never over a file; a global folder of links gets the file beside their targets plus a link. `prompt_save(directory, path, expected, text)` replaces a file by rename, through a link when it is one, and refuses when it no longer holds `expected`. `prompt_send(pane, text)` (`queue::send`) runs `herdr agent prompt <pane> <text>` like `queue_prompt`, at the agent in a pane whatever its name; `queue::open` also takes `p<digits>` names, the library's new-tab runs. This machine only. See [plan-prompt-library.md](plan-prompt-library.md). |
| `team.rs` | `start_team(workspace_id, directory, members)`: opens a tab per team member, named after its role, with `herdr tab create`, then types `claude --agent <agent>` into its pane with `herdr pane run`, using `tab_move.rs`'s CLI helpers. Role and agent names are refused unless they are plain words. `create_team(directory)` writes the starter team from `templates/team/` (New Team on a workspace's right-click), never over an existing file. `create_agent(directory, agent)` writes one role's `.claude/agents/<agent>.md`, from its starter or a stub, never over an existing file. This machine only. See [team.md](team.md). |
| `lib.rs` | Registers the plugins, state and commands. On macOS it also sets the app menu from `menu.rs`. |
| `menu.rs` | macOS only. The app menu is Tauri's default one (About, Services, Hide, Quit, and the Edit menu whose Copy, Paste and Select All the terminal and text fields rely on) plus **Settings…** (⌘,) after About. A click emits `menu://open_settings` to the webview, and `App.tsx` runs the catalog's `open_settings` command for it. The item owns ⌘,, so `Controller.shortcut` leaves that key alone on macOS and the dialog opens once. |
| `settings.rs` | The settings file and theme folders: see [settings.md](settings.md). `settings_load` reads `~/.config/herdr/config-tauri.toml` (`$XDG_CONFIG_HOME/herdr/`) as JSON, `{}` with the parser's message when it does not parse, so the window still opens; `settings_set(key, value)` writes one key (one or two lowercase words, a string without control characters, a number or a boolean; null removes it) with `toml_edit`, keeping comments and layout, through a temporary file renamed over, and through the symlink when the file is one, so a provisioned file stays a link into dotfiles; a file that does not parse is refused rather than rewritten. `theme_list` lists the Ghostty theme folders herdr-gpui reads; `theme_read(name)` reads a name only from inside one of them (resolved through symlinks, refused when it leaves the folder) and a `~/` or absolute path only when the file's own `theme` value names it, at most 64 KiB. This Mac's, whichever host the window is attached to. |
| `osc52.rs` | Bounded base64 to UTF-8 decoding for the daemon's clipboard writes. |
| `error.rs` | The crate's `thiserror` enum. It serializes as its message at the webview boundary. |

None of the commands block: each one queues on the connection's bounded queue. A reconnect replaces the
handle, and the old worker stops on its own thread.

When Herdr changes its protocol, follow `src-tauri/src/herdr/NOTICE.md`: copy the changed declarations
from that release and run the live test against a daemon of that version.

## Input rules carried over from herdr-gpui

- Plain printable text goes through the textarea's `input` event as `TextCommit`, never through keydown. That
  keeps keyboard layouts, dead keys, and IME composition working.
- Ctrl and Option chords send the physical key (`Option-P` sends Alt+`p`, not `π`).
- Cmd chords belong to the app: catalog shortcuts run as commands, and Cmd-V pastes.
- Option-arrows are the app's too, as Herdr's `[keys]` bind them: Up and Down step through workspaces
  (wrapping, window-side in `app/step.ts`), Left and Right through tabs. Text fields keep them for word moves.
- When a pane reports the mouse or is on the alternate screen, the wheel sends one event per line.
  Otherwise it sends one event carrying the whole count, which Herdr scrolls the scrollback by.

## Adding things

- **A command**: add it to `DEFINITIONS` in `src/app/catalog.ts` with its keys and the request it builds,
  and allow its method in `METHODS` in `commands.rs`. A one-off daemon call from a view can use
  `controller.request(method, params)` directly.
- **A window-only command**: give it `action: "window"` in the catalog and handle it in `Controller.run`.
- **UI**: write React components in `src/components`. They hot-reload under `npm run tauri dev`.
